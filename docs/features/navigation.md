# 기능: 탐색·정렬

## 화면 구성

- **드라이브 목록** (시작 화면): 경로를 비워두면(`null`) 이 화면이 나온다. `DriveInfo.GetDrives()`로
  연결된 드라이브를 나열하고, 각 드라이브의 "디스크 사용량"은 `TotalSize - AvailableFreeSpace`로
  즉시 계산한다(파일을 순회할 필요가 없어 빠르다).
- **폴더 보기**: 현재 폴더의 하위 폴더 + 파일을 나열한다. 폴더는 재귀 크기 계산이 끝날 때까지
  "계산 중..."으로 보이다가 값이 채워진다.

## 이동 방법

| 동작 | 방법 |
|---|---|
| 상위 폴더로 | 툴바의 위쪽 화살표 버튼 |
| 특정 폴더로 | 경로 입력창에 직접 입력 후 Enter |
| 폴더 선택 대화상자로 | "찾아보기" 버튼 (`System.Windows.Forms.FolderBrowserDialog` 사용) |
| 하위 폴더로 들어가기 | 목록에서 폴더 행 더블클릭 |
| 파일 열기 | 목록에서 파일 행 더블클릭 (운영체제 기본 프로그램으로 실행) |
| 탐색기에서 보기 | 행 우클릭 → "탐색기에서 열기" (`explorer.exe /select,"경로"`) |
| 다시 계산 | "새로고침" 버튼 (현재 폴더를 다시 스캔) |

## 정렬

**기본값은 이름 오름차순**이고, 정렬 기준과 무관하게 **폴더가 항상 파일보다 위**에 온다
(탐색기와 같은 관례). 열 머리글(이름/종류/디스크 사용량)을 클릭하면 그 기준으로 정렬하고,
같은 열을 다시 클릭하면 오름차순/내림차순이 바뀐다. 이 선택은 드라이브 목록과 폴더 뷰에
공통으로 적용되고 탐색하는 동안 유지된다.

WPF의 `CollectionViewSource.GetDefaultView(...)` 로 `ObservableCollection`에 두 단계
`SortDescription`(1차: `IsDirectory` 내림차순, 2차: 사용자가 고른 열)을 적용하는 방식이라,
백그라운드에서 크기 값이 갱신돼도 목록이 자동으로 다시 그려진다. 기본값이 크기순이 아니라
이름순인 이유 중 하나는, 크기순일 때 폴더 크기가 백그라운드에서 서서히 채워지며 행 순서가
계속 들썩이는 문제가 있었기 때문이다 (`docs/troubleshooting.md` 4번).

## 의도적으로 뺀 기능

삭제·이동·이름 변경 등 파일을 "관리"하는 기능은 넣지 않았다. 이 도구는 **보기 전용**이다 —
요청받지 않은 파괴적 기능을 넣어 사고 위험을 늘리지 않기 위함이다.
