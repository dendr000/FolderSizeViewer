# 기능: 폴더 크기 계산

## 이 기능이 왜 필요한가

Windows 탐색기는 파일의 크기는 "크기" 열에 바로 보여주지만, **폴더의 크기는 보여주지 않는다**
(하위 파일을 전부 더해야 하므로 느릴 수 있어 일부러 계산하지 않는 것). 이 앱은 폴더를 선택하면
하위 파일을 전부 재귀적으로 더해 크기를 보여준다.

## 용어

- **논리 크기 (logical size)**: 파일이 "몇 바이트짜리 데이터를 담고 있다고 주장하는지"의 값.
  `.NET`의 `FileInfo.Length`가 반환하는 값이 이것이다.
- **디스크 할당 크기 (size on disk)**: 그 파일이 **실제로 디스크 클러스터를 얼마나 차지하는지**.
  탐색기에서 파일 속성(우클릭 → 속성)을 열면 "크기"와 "디스크 할당 크기" 두 줄이 따로 나오는데,
  이 앱이 보여주는 값은 후자에 해당한다.
- **클러스터(cluster)**: 디스크가 데이터를 저장하는 최소 단위(보통 4KB). 1바이트짜리 파일도
  최소 1클러스터(보통 4096바이트)를 차지한다.
- **희소 파일(sparse file)**: 논리적으로는 크지만 실제로 데이터가 채워지지 않은 구간("구멍")은
  디스크 공간을 전혀 차지하지 않는 파일. 동적으로 커지는 가상 디스크(VHD/VHDX) 등이 대표적인 예다.

## 왜 논리 크기가 아니라 디스크 할당 크기를 쓰는가

2026-10-01, 가상 디스크 파일처럼 **논리 크기는 500GB인데 실제로는 디스크를 거의 안 쓰는** 파일이
있다는 피드백을 받고 바꿨다. 논리 크기만 보면 "이 폴더가 왜 이렇게 큰지" 전혀 알 수 없고, 실제로
비워야 할 공간이 얼마인지도 알려주지 못한다. "폴더가 디스크를 실제로 얼마나 쓰고 있는가"를 보여주는
것이 이 도구의 목적에 더 맞는다.

## 구현 (`DiskSize.cs`)

1. Win32 API `GetCompressedFileSizeW` 로 파일의 실제 할당 크기(압축/희소 파일이면 이미 실사용량,
   일반 파일이면 논리 크기와 같은 값)를 가져온다.
2. `GetDiskFreeSpaceW` 로 그 파일이 있는 드라이브의 클러스터 크기(보통 4096바이트)를 알아내고,
   그 단위로 올림한다. 일반 파일은 이 올림 때문에 탐색기의 "디스크 할당 크기"와 정확히 같은 값이 된다.
3. 드라이브 루트별로 클러스터 크기를 캐시해 반복 조회를 줄인다.

검증: `fsutil`로 1GB 논리 크기의 희소 파일(실제 할당 0)과 29바이트짜리 일반 파일을 만들어
테스트한 결과, 희소 파일은 0바이트, 일반 파일은 4096바이트(1클러스터)로 정확히 계산됨을 확인했다.

## 백그라운드 계산과 취소

폴더 하나의 크기를 구하려면 그 안의 모든 파일을 순회해야 해서 큰 폴더는 시간이 걸린다.
UI가 멈추지 않도록 `Task.Run`으로 백그라운드 스레드에서 계산하고, 폴더를 다시 이동하면
`CancellationTokenSource`로 이전 계산을 취소한다. 계산 중인 행은 "계산 중..."으로 표시되다가
완료되면 실제 크기로 갱신된다 (`RowItem.IsCalculating`).

재귀 깊이는 64단계로 제한해 순환 참조(정션/심볼릭 링크로 인한 무한 루프)를 방지하고,
재분석 지점(`FileAttributes.ReparsePoint`)이 있는 폴더는 따라 들어가지 않는다(중복 계산 방지).
